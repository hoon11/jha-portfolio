# 데이터 운영 데모 검증 기록

확인일: 2026-10-17 JST. 이 기록은 로컬 작업본의 실행 관찰이며 배포 완료를 뜻하지 않는다. 테스트 설계의 원본은 [TEST-DESIGN.md](TEST-DESIGN.md)다.

## 자동 확인

- `npm run test`: 8개 파일, 88개 테스트 통과. 기존 포트폴리오 회귀 테스트를 포함한다.
- `npm run typecheck`: 통과.
- `npm run build`: 통과. 영어·일본어·한국어의 데이터 운영 데모 경로를 정적 생성했다.
- `git diff --check`: 공백 오류 없음. Windows 줄바꿈 안내는 출력됐다.

도메인 테스트는 집계 예시 3,000→12,000→7,000엔, 필터·정렬·달력 날짜·금액 경계·빈 결과·0엔·빠진 날짜를 확인했다. UI 테스트는 편집 초안 분리, 유효성 검사, 저장·취소, 필터 제외 후 포커스, 초기화와 세 언어 입력을 확인했다. T06은 네 탭 왕복 시 미저장 편집 유지를 확인했다.

UI 자동 테스트에서 차트 컴포넌트는 jsdom의 레이아웃 측정 한계 때문에 집계값을 받는 대체 컴포넌트로 바꿨다. 실제 Recharts 렌더링은 아래 브라우저 관찰로 별도 확인했다.

## 실제 브라우저 관찰

- 한국어 데모의 원본 샘플은 20건·완료 12건·매출 21,900엔으로 표시됐다. Recharts 선 그래프 1개와 카테고리 막대 3개가 렌더링됐다.
- ORD-003만 검색한 뒤 상태를 완료, 금액을 4,000엔으로 저장하면 1건·완료 1건·매출 4,000엔으로 갱신됐다. 편집 버튼으로 포커스가 복귀했다.
- 설계 탭을 방문한 뒤 데모로 돌아와도 저장 값과 검색 조건이 유지됐다. 다시 표시된 차트도 렌더링됐다.
- 취소 상태 필터에서 ORD-003을 완료로 저장하면 결과에서 빠졌고, 이유 안내와 주문 결과 제목으로의 포커스 복귀를 확인했다.
- 390px과 320px 뷰포트에서 페이지 전체 가로 넘침이 없었다. 좁은 화면에서 두 그래프의 세로 배치와 축·값을 확인했다.
- 320px에서 ORD-001 검색·상세·1,200엔 저장을 진행해 1건·완료 1건·매출 1,200엔과 포커스 복귀를 확인했다.
- 일본어로 언어를 변경하면 같은 프로젝트 경로에서 원본 20건·12건·21,900엔을 표시했다. 임시 뷰포트 설정은 확인 후 해제했다.

모든 보조기기·모든 기기·대규모 데이터의 검증 결과는 아니다. 새로고침과 언어 이동에서 샘플이 초기화되는 메모리 전용 데모이며 실서버 저장을 제공하지 않는다.

## 의존성 확인

Recharts 3.10.1과 설치된 React 19.3.0에 맞는 react-is 19.3.0을 추가했다. Recharts는 React 19 peer 범위를 지원한다. [공식 구성 안내](https://recharts.github.io/en-US/guide/getting-started/).

`npm audit`에는 기존 `source-map-js` 1.2.1의 high 항목 1건이 남아 있다. 같은 버전이 작업 전 HEAD의 lockfile에도 있었으며 새 Recharts 취약점으로 보고된 것은 아니다. 이 작업에서는 관련 없는 의존성을 자동 변경하지 않았다. [해당 보안 권고](https://github.com/advisories/GHSA-68fv-2mgg-jv7q).

이 기록은 배포 전 로컬 검증이다. 실제 배포 상태와 배포 커밋은 별도로 확인한다.
