# 데이터 운영 데모 테스트 설계

이 문서는 입력·조작·기대 결과의 설계이며 실행 결과가 아니다. 브라우저·모바일 확인 완료를 뜻하지 않는다. 실제 명령과 결과는 실행 로그에서 확인한다. 기능 ID는 [요구사항](REQUIREMENTS.md)의 F01~F10을 사용한다.

## 자동 테스트의 책임

| 코드 | 위치 | 책임 |
| --- | --- | --- |
| D ID | lib/data-operations.test.ts | 날짜·입력 경계, 복합 필터, 정렬과 집계 |
| U ID | components/data-operations-demo.test.tsx | reducer 전이의 입력·저장·취소·초기화, DOM 안내·포커스 |
| T ID | components/project-documents.test.tsx | 네 탭, 선택·패널 관계와 상태 유지 |

구체적인 자동 테스트 ID는 테스트 제목에 표시한다. 아래 A ID는 구현 파일과 독립적인 완료 기준이다. 라이브러리 내부 SVG 좌표를 스냅샷으로 복제하지 않고 입력 데이터·사용자가 읽는 값·실제 렌더링을 확인한다.

## 탭과 실제 브라우저 확인

### 시각적 상태와 행 편집

- U10: 필터를 입력해도 적용 조건과 집계는 바뀌지 않으며 미적용 안내를 표시한다. 잘못된 날짜를 적용해도 마지막 정상 조건과 결과를 유지한다.
- U11: 원래 입력으로 복귀·필터 초기화·샘플 초기화 시 미적용 안내가 사라지고, 시작일이나 종료일만 있는 조건을 설명한다.
- U12: 편집 폼이 선택 주문 바로 다음 표 행에 있고 해당 행에만 선택 표시가 있다. 금액 정렬·상태 배지의 텍스트를 유지하고 저장·취소 뒤 포커스가 복귀한다.

실제 브라우저에서 상단 매출 카드의 순서, 적용 조건과 그래프의 일치, 선택 행 근처의 편집, 모바일 폼 너비, 금액 오른쪽 정렬, 색과 독립적인 상태 문구를 확인한다. 자동 테스트만으로 시각적 완성도를 판정하지 않는다.

T01은 문서 탭의 단일 패널 노출, T02는 좌우·Home·End·양 끝 순환, T03은 유일 ID·aria 연결·hidden·Tab 정지점, T04는 세 언어의 대응 문서, T06은 데모를 포함한 네 탭 왕복 시 편집 초안 유지를 확인한다. T05의 언어별 URL·metadata 검사는 lib/i18n.test.ts에서 수행한다. 새로고침·언어 이동 시 최초 데모와 원본 복원은 브라우저에서도 확인한다.

데스크톱·좁은 모바일 화면에서 Recharts 선·막대, 툴팁·축·엔 단위, 대체 집계 표의 값과 배치를 대조한다. 브라우저 경고·페이지 전체 가로 넘침·키보드 오류 수정과 포커스 복귀를 확인한다. 데모가 외부 저장이나 localStorage 쓰기를 하지 않는지 확인한다. DOM 테스트나 빌드 통과만으로 이 확인의 완료를 주장하지 않는다.
