# 공조 모니터링 콘셉트 설계

작성일: 2026-10-18 JST. [요구사항](REQUIREMENTS.md)의 페이지 분리와 상태 표현을 구체화한다.

## 정보 구조

소개 페이지는 서비스 이해를 목적으로 한다. 첫 화면에 핵심 문구와 설명용 단면도를 배치하고, 선택 정보는 공간·운전·온도만 간결하게 제공한다. 특징과 사용 흐름 뒤에 별도 모니터링 데모로 가는 CTA를 둔다. 전체 목록과 상세 그래프는 이 페이지에 넣지 않는다.

별도 데모는 같은 단면도에 전체 기기 목록·선택 상세·온도 추이를 더한다. 소개로 돌아가는 링크를 제공한다. 포트폴리오의 공통 내비게이션·언어 선택·메타데이터 구조를 유지한다.

## 데이터와 상태

고정 타입과 fixture가 ID·층·공간 키·운전·설정 온도·수신 시각·미수신을 포함한 추이 데이터의 출처다. 번역 모듈은 공간 키와 상태를 각 언어의 표시 문구로 바꾸며 측정값을 별도로 복제하지 않는다.

페이지마다 선택 ID 하나를 관리한다. 단면도·목록·카드·상세·그래프는 같은 ID에서 표시 정보를 구한다. 각 영역에 선택 기기 객체를 중복 저장하지 않는다. 같은 기기를 재선택해도 ID를 유지한다. 페이지 이동·새로고침·언어 전환으로 새 페이지가 시작되면 초기 ID AC-101을 사용한다. 소개 페이지의 문서 탭은 패널을 숨기는 구조로 미리보기 상태를 유지한다.

운전 상태와 갱신 상태는 별개다. 갱신 여부는 고정된 샘플 기준 시점과 수신 시각으로 설명한다. 방문자의 시계나 타이머를 사용하지 않는다. AC-301의 이전 값은 마지막 수신값이라고 표시하며 고장이나 운전 정지를 추론하지 않는다.

## 단면도와 접근성

단면도는 설명용 2D 건물 표현이다. 3개 층과 공간 이름, 설치된 공조기를 글자로 식별할 수 있게 한다. 기기 선택은 네이티브 버튼으로 제공하고 aria-pressed와 보이는 선택 표시를 함께 사용한다. 선택과 키보드 포커스를 다른 의미로 표현한다. 선택 시 버튼 포커스를 유지하고, 필요한 경우 별도 상세 이동 링크를 제공한다.

모니터링 목록에서도 모든 기기를 선택할 수 있다. 좁은 화면에서는 단면도와 정보 영역을 세로로 쌓는다. 필수 정보를 hover나 색만으로 전달하지 않는다.

## 온도 추이

기존 의존성인 Recharts로 선택 기기의 °C 꺾은선 그래프를 그린다. 기기를 바꿔도 비교 기준이 바뀌지 않도록 샘플 범위에 맞는 20–30°C 축을 사용한다. 시각과 단위를 표시하고 같은 데이터로 표를 제공한다. null은 미수신이며 connectNulls=false로 선을 끊는다. 누락값을 0으로 채우거나 현재 온도를 추정하지 않는다. 샘플 기준 시점과 마지막 수신 시각을 구분한다.

## 실행 경계

Next.js 정적 언어 경로와 기존 문서 탭을 재사용한다. 데이터와 문서는 공개 가능한 독립 콘셉트만 포함한다. 상호작용에 필요한 선택과 차트만 클라이언트 경계를 사용한다. 실제 API·DB·저장소·제어 기능은 추가하지 않는다.

UI 문서 탭과 이 문서는 기능 의도를 설명한다. 실제 확인 결과는 별도 검증 기록에 남기며 [테스트 설계](TEST-DESIGN.md)의 기대 결과를 통과 기록으로 간주하지 않는다.
